# 06 · 模块 topic 地图与开发方向

> Historical topic map. For the current v0.2 status, see `README.md` and `12-assistant-architecture.md`; the current roadmap is scenario-based (S1–S6).

> 没有产品经理给我们出需求，就自己从家庭生活里“生成需求”。
> 这不是拍脑袋：用频率、痛点、数据、AI 价值、成本、依赖来筛；先做闭环，不做功能点。
> 参考入口见 [`07-reference-index.md`](07-reference-index.md)；已有软件见 [`08-existing-software.md`](08-existing-software.md)；家庭场景见 [`05-family-scenarios.md`](05-family-scenarios.md)。

---

## 1. 先定原则

1. **家里真的发生**：不是“看起来像个平台”，而是这周就会用。
2. **一个人 + AI 能做完**：一个闭环最好一个周末能看到结果。
3. **能产生数据**：做完之后，下个功能有东西可用（库存 → 菜单 → 采购 → AI）。
4. **AI 是增强，不是前提**：没有 AI 也能用；AI 失败不影响核心。
5. **能验证**：有明确的“算做完了”的标准，不是“页面画出来了”。
6. **允许以后不做**：候选 topic 很多，先选 1–2 个，其他进 backlog。

## 2. 怎么从家庭生活里生成需求

### 2.1 一周家庭日志

连续一周，记录 10 个“烦/忘了/重复”的瞬间：

- 忘了冰箱里有什么，重复买。
- 不知道今晚吃什么，最后点外卖。
- 菜谱收藏了很多，真正做的时候找不到。
- 东西过期了才发现。
- 想记一件事，但打开 App 太麻烦。
- 家人问“那个东西放哪了”，答不上来。
- 想查“宝宝/绿萝/食物保存”，搜出来一堆广告。

然后给每条打标：**频率 / 痛感 / 现有替代 / 是否愿意用新工具 / 是否能被 AI 帮**。

### 2.2 JTBD 句式

```text
当我（场景）时，
我想（动作），
这样我就能（结果）。
```

例子：

- 当我下班回家时，我想 30 秒内知道“今晚能做什么”，这样我就不用点外卖。
- 当我买菜前，我想知道“这周菜单缺什么”，这样我就不会漏买/重复买。
- 当我拍一张小票时，我想它自动变成草稿，这样我只需要确认，不用逐条录入。

### 2.3 评分表

| 维度 | 说明 |
|---|---|
| 频率 | 每天 / 每周 / 每月 / 偶尔 |
| 痛感 | 1–5，越烦越高 |
| 数据 | 现在有没有数据？能不能低成本产生？ |
| AI 杠杆 | AI 是“省事很多”，还是“为了用 AI 而用 AI”？ |
| 成本 | S（一个周末）/ M（1–2 周）/ L（一个月+） |
| 依赖 | 依赖哪个模块/外部服务？ |
| 风险 | 隐私/健康/误操作 |
| 热情 | 你自己想不想做？单人项目这点很重要 |

**通过门槛**：频率高或痛感强 + 数据可得 + 一个闭环能做完。
**不通过**：只是“看起来高级”，但家里不用，或者依赖还没建好。

## 3. 模块 topic 地图

### 3.1 home-core

| 模块 | 家庭问题 | 候选 topic | 依赖 | 优先级 |
|---|---|---|---|---|
| `catalog` | 这东西叫什么、放哪、什么单位 | 物品/别名、分类、位置（冰箱/冷冻/柜子）、单位、条码、图片、标签（过敏/儿童） | — | P1 |
| `inventory` | 家里还有多少、什么时候过期 | 批次、入库/出库/调整、流水、当前数量、临期、低库存、盘点、浪费、位置转移 | catalog | P1 |
| `recipe` | 这周能做什么 | 菜谱/食材/步骤、份数、时间、标签（快手/儿童/素食）、缩放、替换、来源、上次做 | catalog | P2 |
| `meal_plan` | 一周吃什么、缺什么 | 周视图、早/午/晚、份数、从库存生成、采购清单、合并单位、偏好/忌口、剩菜复用 | recipe、inventory | P2 |
| `task` | 该做的事老忘 | 待办、重复任务、提醒、由库存/菜单触发、Today 视图、稍后/跳过 | shared | P3+ |
| `integration` | 数据怎么进出 | CSV/JSON 导入导出、Webhook、飞书通知、条码查询、备份 | 各模块 public | 以后 |
| `reporting` | 家里最近怎么样 | 低库存/临期看板、月度消耗/浪费、采购花费（以后） | 各模块只读 | 以后 |
| `plants` | 绿萝/多肉怎么养 | 植株、浇水/光照/换盆、照片、提醒、知识问答 | task、knowledge | 以后 |
| `budget` | 这个月花在哪 | 支出、分类、小票、月度汇总 | intake、reporting | 以后 |
| `journal` | 想留点家庭记忆 | 时间线、照片、里程碑、月报 | storage | 以后 |
| `health` | 家人健康/成长记录 | 体重/睡眠/喂养/疫苗；高隐私、高风险 | — | 以后（谨慎） |
| `chores` | 家务怎么分 | 任务、轮换、积分；先并入 task | task | 以后 |

### 3.2 home-ai

| 模块 | 家庭问题 | 候选 topic | 依赖 | 优先级 |
|---|---|---|---|---|
| `intake` | 拍照能不能少打字 | 小票、食材、菜谱页、药品、植物照片；OCR/VLM、结构化、置信度、去重/匹配、批量、重试 | platform、core_client | P3 |
| `knowledge` | 这个说法靠谱吗 | 育儿/食材/健康/养花域；摄取、切分、混合检索、重排、引用、拒答、评测、知识过期 | platform、core_client | P4 |
| `tools` | AI 怎么安全地办事 | 工具注册、输入/输出 schema、风险等级、确认、幂等、超时、审计 | core_client、intake、knowledge | P5 |
| `agent` | 能不能一句话查/记 | 意图、补槽、澄清、单步查询、单步写确认、对话摘要、错误解释 | tools、platform | P5 |
| `agent_runtime` | 多步任务怎么办 | LangGraph/DSH、checkpoint、interrupt、审批、预算；**等真实任务再上** | agent、tools | P6+ |

### 3.3 平台能力

| 模块 | 提供什么 | 什么时候做 |
|---|---|---|
| `shared` | IDs、时间、错误、分页、事件、actor、日志 | P0 |
| `llm` | provider 适配、prompt、重试、成本 | P3 前 |
| `storage` | 本地文件；以后 MinIO | P3 前 |
| `jobs` | jobs 表 + worker；重试/DLQ | P3 前 |
| `core_client` | 调 core API 的 typed client | P3 前 |

## 4. 先做哪个：推荐顺序

| 阶段 | 模块 | 为什么 |
|---|---|---|
| **P1** | `catalog` + `inventory` + Web | 每天/每周都用；不需要 AI；能立刻验证“库存是否可信” |
| **P2** | `recipe` + `meal_plan` + daily digest | 把库存变成“这周吃什么/缺什么”；顺带推低库存/临期/菜单摘要 |
| **P3** | `intake` | 只有在库存存在后，拍照入库才有意义 |
| **P4** | `knowledge` | 需要语料/评测/引用；先一个领域，别铺开 |
| **P5** | `tools` + `agent` | 需要前面的数据和工具；先做入口，不做编排 |
| **P6+** | `agent_runtime` | 等第一个真实多步任务（例如“排一周菜单 + 生成采购 + 建提醒”） |

**先不做**：task/integration/reporting/plants/budget/journal/health。
它们不是不重要，而是**没有前两条闭环时，做了也没人用**。

## 5. 每个模块的“第一个 slice”

| 模块 | 第一个 slice 只做什么 | 验收 |
|---|---|---|
| `catalog` | 物品名、分类、位置、单位；列表/搜索 | 能新增/编辑/搜索 20 个物品 |
| `inventory` | 入库/出库/调整；当前数量；低库存；quick add | 数量对得上；流水能解释；新增一件物品不用走长表单 |
| `recipe` | 10 道家常菜；食材/步骤/份数 | 能按食材搜；能按份数缩放 |
| `meal_plan` | 周视图；加菜谱；生成采购清单 | 清单合并同类项；能勾选 |
| `intake` | 一种图片（小票或食材）；草稿/确认 | 低置信可改；重复提交不重复入库 |
| `knowledge` | 一个领域；20 篇文档；引用/拒答 | 有出处；不知道就说不知道 |
| `agent` | 5 个意图；只读为主；一个写操作确认 | 不乱调工具；写前有确认 |

> 每个 slice 都要有：模块 README、单元测试、至少一个 API/契约测试。
> P2 后半再加 daily digest（低库存/临期/菜单摘要），先规则，不接 LLM。

## 6. 可以拿来讨论的问题

1. 过去一周，你家最烦的 3 件事是什么？分别属于哪个模块？
2. 你现在手里已经有什么数据？（菜谱、库存、育儿/养花笔记、照片）
3. 哪个 AI 能力你愿意为它多花一点钱/时间？（拍照入库 / 知识问答 / 自然语言入口）
4. 哪个功能你**每周都会用**？哪个只是“看起来很酷”？
5. 哪个模块你最有热情做？（单人项目，热情是可持续性的一部分）
6. 未来 4–6 周，你能稳定投入多少小时/周？

> 建议：先选 1 个“高频痛点” + 1 个“你最有热情”的，但**核心闭环必须先做库存/菜单**。
