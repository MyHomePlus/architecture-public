# 04 · 设计亮点与取舍

> 这不是功能清单，而是这个架构里几个“为什么这样选”的关键决定。
> 状态：v0.2 架构完成；实现从 P0 开始。没有实测的数字不写。

---

## 1. 三个程序，不是六个服务

**问题**：资源、拍照识别、知识库、Agent 看起来是四块，很容易拆成 4 个服务 + 网关 + 4 个库。

**选择**：只保留 3 个程序：

- `home-web`：界面
- `home-core`：Django，业务真相源
- `home-ai`：FastAPI，识别/知识/Agent 模块

**代价**：AI 的依赖都在一个镜像里；模块之间要靠纪律，不能靠网络边界。

**收益**：少两个服务的部署/联调/监控；一个人 + AI 能同时 hold 住。

图：[`01-overall`](../diagrams/01-overall.puml)

---

## 2. 库存只有一条流水

**问题**：直接改“当前数量”很爽，但改错了不知道改了什么，也没法回滚。

**选择**：库存只追加流水（入库/出库/调整/过期），当前数量 = 流水求和；批次单独记，用于保质期。

**代价**：写多一条流水；查当前数量要聚合/投影；不能随手改历史。

**收益**：可追溯、可冲正、可重算；以后做临期/低库存不用再补审计。

图：[`05-data-ownership`](../diagrams/05-data-ownership.puml)

---

## 3. AI 只交草稿，人确认才入库

**问题**：拍照识别一定会错；如果识别完直接写库存，错一次就要手工擦屁股，还可能重复写。

**选择**：`intake` 只产出草稿（items + confidence + 原图）；人确认/修正后，才经 core API 提交；提交带幂等键。

**代价**：多一步确认；低置信时要人改。

**收益**：AI 出错不污染真相；重复提交不会重复入库；以后可以换模型/provider。

图：[`04-write-path`](../diagrams/04-write-path.puml)

---

## 4. 模块是文件夹，不是微服务

**问题**：一个人 + AI 写代码，最容易变成“到处 import、改一处崩三处”。

**选择**：每个功能一个 vertical slice：`api / contracts / services / models / events / tests / README`；模块只暴露 `contracts.py` + `services.py`；不跨模块 import models、不建跨模块 FK/JOIN。`reporting` 是唯一只读例外。

**代价**：有时要多写一层 DTO；跨模块展示要多一次查询/组装。

**收益**：新功能 = 新目录 + 注册一行；AI 不需要理解全仓库；以后拆服务是搬家，不是重写。

图：[`07-module-anatomy`](../diagrams/07-module-anatomy.puml)

---

## 5. 先 PostgreSQL + 本地盘，够用再长

**问题**：企业习惯是 Redis + MinIO + 网关 + 消息队列一起上；家庭项目根本用不到。

**选择**：1 个 PostgreSQL、2 个 schema；图片/文档先放本地卷；长任务先用 `jobs` 表 + worker；Redis/MinIO/Caddy 有真实需求再加。

**代价**：高并发/多实例能力弱；以后要迁。

**收益**：部署简单、备份简单、一个人能维护；先把真实闭环跑出来。

图：[`06-deployment`](../diagrams/06-deployment.puml)

---

## 6. pi-agent 只做入口，不急着上编排

**问题**：很容易一上来就 LangGraph/多 Agent/审批/checkpoint，结果没有真实多步任务，全是空转。

**选择**：pi-agent 只做意图/补槽/路由；`tools` 是唯一业务桥；多步编排等第一个真实任务出现，再作为新模块加。

**代价**：现在不能自动完成复杂多步任务；有些事要人点几下。

**收益**：入口轻、延迟低；工具/业务不被 Agent 框架绑死；以后加编排不改现有模块。

---

## 这套项目想证明什么

1. **能在约束下做减法**：3 个程序、1 个库、1 个写入口；主动不做微服务/网关/消息队列。
2. **能设计数据边界**：库存流水、草稿/确认、知识只读；谁写什么、写错了怎么恢复，是清楚的。
3. **能判断 AI 的边界**：能用 SQL/表单的不用模型；能用入口 Agent 的不用编排；知识只读、草稿不写真相。
4. **能一个人 + AI 持续交付**：模块模板、AGENTS.md、完工检查清单、检查脚本；先跑通再抽象。
5. **能承认代价**：少一些企业能力（多租户/RBAC/K8s/事件总线），换更快的真实使用和更低的维护成本；这是选择，不是做不到。
